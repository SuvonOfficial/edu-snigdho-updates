# Edu Snigdho আপডেট সার্ভার (GitHub)

এই রিপোজিটরি থেকে আপনি Edu Snigdho থিম চালু থাকা সব সাইটে নিয়ন্ত্রণ করতে পারবেন:

- **নতুন ভার্সনের নোটিফিকেশন:** ক্রেতা (সাইটের মালিক) নতুন ভার্সনের খবর ও পরিবর্তনের তালিকা দেখবেন।
- **CSS/JS ফিক্স অটো আপডেট:** `src/patch.css` ও `src/patch.js` বদলে রিলিজ দিলে সব সাইটে নিজে থেকে প্রয়োগ হবে।
- **জরুরি বার্তা:** সব সাইটে (বা শুধু মালিকদের) উপরে একটি বার্তা-বার দেখানো যাবে।

## নিরাপত্তার নকশা

প্রতিটি রিলিজ আপনার **গোপন কী** (`private.jwk.json`) দিয়ে স্বাক্ষর করা হয়। থিমের ভেতরে শুধু **পাবলিক কী** থাকে। থিম প্রথমে স্বাক্ষর এবং প্রতিটি ফাইলের SHA-256 হ্যাশ যাচাই করে, মিললে তবেই প্রয়োগ করে। তাই কেউ আপনার GitHub অ্যাকাউন্ট দখল করলেও স্বাক্ষর ছাড়া ক্রেতার সাইটে কোড চালাতে পারবে না। তবে গোপন কী ফাঁস হলে সেই সুরক্ষা থাকে না, তাই এটা সবচেয়ে সাবধানে রাখুন।

## একবারের সেটআপ

1. GitHub-এ নতুন **Public** রিপোজিটরি বানান, যেমন `edu-snigdho-updates`।
2. এই ফোল্ডারের সব ফাইল (`private.jwk.json` ছাড়া, ওটা এখনো নেই) রিপোজিটরিতে তুলুন।
3. কম্পিউটারে Node.js (সংস্করণ ১৮ বা তার বেশি) ইনস্টল করুন, তারপর রিপোজিটরির ফোল্ডারে চালান:

   ```
   node tools/release.mjs init
   ```

   এটি `private.jwk.json` বানাবে এবং `pub:{kty:'EC',...}` ধাঁচের একটি লাইন দেখাবে।
4. **`private.jwk.json` ফাইলের একাধিক ব্যাকআপ রাখুন** (পাসওয়ার্ড ম্যানেজার বা অফলাইন ড্রাইভে)। এটি কখনো GitHub-এ তুলবেন না (`.gitignore` এ বাদ দেওয়া আছে)। হারিয়ে ফেললে আর কোনো আপডেট পাঠাতে পারবেন না।
5. থিমের XML ফাইল খুলে `Edu Snigdho: GitHub আপডেট লোডার` লেখা অংশ খুঁজুন। `CFG`-এ দুটি জিনিস বসান:
   - `base`: আপনার GitHub Pages ঠিকানা `https://` ছাড়া, যেমন `myname.github.io/edu-snigdho-updates`
   - `pub`: ধাপ ৩-এর লাইনটি (`pub:` সহ নয়, শুধু `{kty:...}` অংশ)
6. প্রথম রিলিজ বানান এবং push করুন:

   ```
   node tools/release.mjs release --version 1.0.0
   git add docs && git commit -m "release 1.0.0" && git push
   ```
7. GitHub-এ রিপোজিটরির **Settings**, তারপর **Pages** খুলুন। **Branch** `main` এবং **Folder** `/docs` বেছে **Save** করুন। কয়েক মিনিট পর `https://আপনার-ঠিকানা/manifest.json` খুললে ফাইলটি দেখা যাবে।
8. এই XML ফাইলটিই ক্রেতাদের দিন।

## প্রতিদিনের কাজ

**CSS বা JS ফিক্স পাঠানো**

`src/patch.css` বা `src/patch.js` এ ফিক্স লিখুন, তারপর:

```
node tools/release.mjs release --version 1.0.1 --note "ফোনে মেনুর ফিক্স"
git add docs && git commit -m "release 1.0.1" && git push
```

প্রতিটি ফাইল নিজের হ্যাশের নামে (`patch.xxxxxxxxxx.css`) জমা হয়, তাই ব্রাউজারে পুরনো ক্যাশ নিয়ে সমস্যা হয় না। ফিক্স তুলে নিতে ফাইলটি ফাঁকা (শুধু মন্তব্য) করে নতুন রিলিজ দিন।

**জরুরি বার্তা**

```
node tools/release.mjs release --notice "আগামীকাল রাত ১২টায় আপডেট চলবে" --id n1 --audience all --level warn --until 2026-12-31
```

- `--audience`: `all` হলে সাইটের সব দর্শক দেখবে, `owner` (ডিফল্ট) হলে শুধু সাইটের মালিক দেখবেন।
- `--level`: `info` (সবুজ), `warn` (কমলা), `critical` (লাল)
- `--until`: এই তারিখের পর বার্তা নিজে থেকে বন্ধ হবে (ঐচ্ছিক)
- `--link`: `https://` দিয়ে শুরু হওয়া বিস্তারিত পাতার লিংক (ঐচ্ছিক)
- ব্যবহারকারী বন্ধ করলে ওই বার্তা (`--id` ধরে) তার ব্রাউজারে আর দেখাবে না। নতুন বার্তায় নতুন `--id` দিন।
- বার্তা সরাতে: `node tools/release.mjs release --clear-notice`

বার্তা বদলাতে `--version` দিতে হয় না, আগের ভার্সনই থাকে।

**নতুন XML ভার্সন বের করা**

1. থিম XML-এর `CFG.version` বাড়ান (যেমন `1.1.0`) এবং নতুন XML ফাইল ক্রেতাদের দিন।
2. একই সংখ্যায় রিলিজ দিন:

   ```
   node tools/release.mjs release --version 1.1.0 --note "নতুন গ্যালারি" --note "ফোনের ফিক্স"
   ```

   এতে যাদের XML পুরনো, সেই মালিকরা (নিচে দেখুন) "নতুন ভার্সন এসেছে" বার্তা দেখবেন।

## মালিকরা কীভাবে নোটিফিকেশন দেখেন

নোটিফিকেশন সাধারণ দর্শকদের দেখানো হয় না। যে ব্রাউজারে মালিক **প্রশাসক লগইন** পেজ থেকে সাইন ইন করেছেন, শুধু সেখানেই নতুন ভার্সনের বার দেখায়। কোনো ব্রাউজারে হাতে চালু করতে সাইটের ঠিকানার শেষে `#edu-owner` যোগ করে একবার খুলুন।

## সীমাবদ্ধতা ও জেনে রাখুন

- অটো আপডেট শুধু CSS/JS ফিক্স পাঠায়। থিমের কাঠামো (HTML বা গ্যাজেট) বদলাতে হলে ক্রেতাকে নতুন XML Restore করতে হবে।
- আপডেট কয়েক মিনিট থেকে প্রায় ১ ঘণ্টা পর সব সাইটে পৌঁছায় (GitHub Pages ও ব্রাউজারের ক্যাশের কারণে)।
- এই ব্যবস্থায় ক্রেতার সাইটের দর্শকদের ব্রাউজার `github.io` থেকে আপডেট ফাইল নেয়। অর্থাৎ GitHub ওই অনুরোধগুলো দেখতে পায়। ক্রেতাদের এ কথা জানিয়ে রাখা ভালো।
- ব্লগার লেআউট এডিটর, `localhost` ও blogger.com প্রিভিউতে লোডার বন্ধ থাকে।
- GitHub অ্যাকাউন্টে **দুই ধাপের যাচাই (2FA)** চালু রাখুন। স্বাক্ষর থাকায় ঝুঁকি অনেক কমে, তবু এটা জরুরি।
- গোপন কী বদলাতে হলে (ফাঁস হলে) নতুন `init` করে নতুন `pub` সহ নতুন XML সবাইকে দিতে হবে। পুরনো XML-এর সাইট আর আপডেট নেবে না।
